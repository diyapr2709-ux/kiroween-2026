## Paste into Kiro (start of brief)

You are building the **web card reader** for Hollerith's Ghost: a static page that replays the answer
to a question as a deck of IBM 80-column punched cards passing through a card reader, with a green-bar
listing that cites each card. **Design is scored; the hosted URL is a published requirement.**

Read first, do not modify: `src/hollerith/trace.py` (trace JSON schema in the module docstring),
`src/hollerith/hollerith_code.py` (`Card.holes` → 12 × 80 hole matrix; row order 12, 11, 0, 1–9),
`src/hollerith/code_table.py` (column layout), `.kiro/steering/product.md`, `.kiro/steering/hollerith.md`.
Run `uv run hollerith ask "Who founded the Tabulating Machine Company?" --json` and
`uv run hollerith ask "Who founded the Tabulating Machine Company?" --pull 2 --json` to see real traces.

Produce a spec (requirements → design → tasks, **≤ 8 tasks**), then implement. If a task fails twice,
simplify the task in the spec.

### Architecture (fixed)
- `web/` holds a **static site**: `index.html`, `reader.css`, `reader.js`, no framework, no build step,
  no backend, no network calls except loading its own JSON files. Plain ES modules.
- `web/data/traces.json` — precomputed traces for the **suggested questions**, generated by a new CLI
  command you add: `hollerith precompute --out web/data` which (a) writes `traces.json` for the
  questions in `web/data/questions.json` (start with the four below), each with its direct trace and
  its **pull** variants (one per card on the direct path, `--pull <seq>`), (b) writes `deck.json`
  (every card: `seq`, `line`, fields, and `holes` as 12 strings of `.`/`O`) so the page can decode any
  card, and (c) writes `entities.json` and `relations.json` for type-ahead chips.
- Typed questions resolve **client-side**: match the longest entity name/alias in `entities.json`
  and a relation from the chips; look the pair up in `traces.json` if present, otherwise show a direct
  card from `deck.json` if one exists, otherwise `NO CARDS, NO ANSWER`. Label this mode
  `LISTING MODE — full walk in CLI`. Never invent a card.
- Hosting: GitHub Pages from `web/` (`.github/workflows/pages.yml` deploying the `web/` directory on
  push to `main`). The README gets the URL.

### Suggested questions (hopper)
1. "Who founded the Tabulating Machine Company?" (direct card; pulling it makes the walker route via LED BY)
2. "What was CTR renamed to?" (direct; pull → walker)
3. "Where did Grace Hopper work?" (three direct cards; pull one → another)
4. "Who founded Ferranti?" (no card → the walker jams: "unknown path shape" — the honest "I don't know")

### Visual language (from the product-design arena report)
- Room: charcoal `#1B1D1F`. Cards: manila `#F2E6CC`, clipped top-left corner, 80 columns × 12 rows of
  rectangular holes, printed text along the top edge in **IBM Plex Mono** (Google Fonts), pre-printed
  field bands labelled SUBJECT / RELATION / OBJECT / SRC / SEQ at columns 1–20 / 21–35 / 36–55 / 56–63 /
  73–80. Labels in IBM Plex Sans Condensed.
- Holes glow amber `#FFB000` when a card is read. Red CHECK lamp `#D7263D` on a jam.
- Listing: green-bar paper (`#DDE8D0` / `#CFE0C3` stripes), Plex Mono, one line per card, `[seq]`
  citations are links that highlight the card.

### Behaviour (MUST, in this priority order)
1. **Reader animation (the one animation):** cards drop from the hopper into the stacker one at a time,
   ~700 ms apart (CSS `animation-delay`), each with a whole-card amber glow as it is read, in step with
   one listing line printing. Then the ANSWER line prints.
2. **Jam:** the card tilts in the throat, the CHECK lamp lights, the card slides to a visible **reject
   pocket**, and the listing prints the `JAM:` line from the trace. No answer is shown.
3. **`[seq]` citations** in the listing are clickable and highlight that card in the stacker.
4. **Hover a column** on any card to see its character and hole rows (e.g. `H = 12-8`), decoded from
   `holes` — this is what makes the holes legible.
5. **Type-ahead chips:** the question box offers entity and relation chips from the JSON files, so a
   typed question always resolves to something the deck can answer or to `NO CARDS`.
6. **Pull a card:** each card in the stacker has a PULL control. Pulling swaps in the trace's `--pull`
   variant (precomputed), which re-runs the reader: the answer either reroutes through other cards or
   jams. The pulled card sits in the reject pocket.
7. `NO CARDS, NO ANSWER` renders as a single blank card with the phrase printed on it.
8. Works at phone width (16 px gutters, no horizontal scroll); keyboard: Enter asks, Esc clears.

### Not in scope
Sound, physics, LLM calls, accounts, share URLs, PNG export, the keypunch animation (stretch, only if asked).

### Definition of done
- `uv run hollerith precompute --out web/data` regenerates every JSON file; the page loads with
  `python -m http.server -d web` and shows the four suggested questions.
- All four hopper questions play end to end; question 4 jams with the lamp; pulling card 00000002
  on question 1 reroutes via `[00000050]`.
- `uv run pytest -q` passes (add tests for `precompute`: JSON shapes, every trace's `seq` exists in
  `deck.json`, every hole string is 80 chars).
- GitHub Pages workflow deploys; the URL opens on a phone.
- Commits in order: spec → precompute command → static page → workflow.
